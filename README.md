# بوابة استثمار المواقع الحكومية — دائرة البلدية بالسويق

نظام إلكتروني لتقديم طلبات **استثمار المواقع الحكومية** و**تجديد العقود** و**التنازل عنها**،
مع مسار اعتماد بين الأقسام، وإشعارات داخل الموقع وبريد إلكتروني، ولوحة تحكم كاملة لمدير النظام.

بُني بـ **Next.js 14 (App Router) + TypeScript + Tailwind CSS + Supabase (PostgreSQL + Storage)**.

---

## ١. الخدمات الثلاث للمواطن (بدون تسجيل دخول)

| الخدمة | المرفقات المطلوبة |
|---|---|
| طلب استثمار موقع جديد | رسالة الطلب • السجل التجاري • التصور المبدئي للموقع |
| تجديد عقد سابق | خطاب طلب التجديد • نسخة من العقد السابق |
| التنازل عن موقع | رسالة التنازل • صورة الموقع بعد الإخلاء • المخالصة المالية |

في كل الطلبات يُدخل المواطن: **الرقم المدني بالأرقام الإنجليزية**، و**الاسم الثلاثي بالعربي**، و**رقم الهاتف**.
كل مرفق يُقبل بصيغة **PDF أو صورة** (JPG / PNG / WEBP) بحد أقصى ١٠ ميجابايت.

يتابع المواطن طلبه من صفحة `/track` بإدخال رقمه المدني — وتظهر له حالة الطلب، وقرار كل جهة
وملاحظاتها، وفي حال الرفض: **الجهة الرافضة واسم صاحب القرار وسبب الرفض**.

## ٢. مسار الطلب

```
تقديم الطلب
   ├─ قسم الشؤون الفنية            ─┐  (القرار من القسمين معاً)
   └─ قسم الرقابة الغذائية والصحية ─┘
          │  رفض من أي قسم ⇒ يُغلق الطلب ويُسجَّل اسم الجهة وصاحب القرار والملاحظات
          ▼  موافقة القسمين
   قسم الشؤون المالية  ⇒ تحديد: تم الدفع / معفى / لم يتم الدفع (+ المبلغ ورقم الإيصال)
          ▼
   دائرة الاستثمار  ⇒  الاعتماد النهائي أو الرفض
```

عند وصول الطلب لأي جهة: يُنشأ **إشعار داخل الموقع** لكل موظفي القسم (مع عدّاد في الشريط العلوي)
و**يُرسل بريد إلكتروني** لكل موظف فيهم.

## ٣. حسابات الموظفين

- الدخول بـ **الرقم الوظيفي + كلمة المرور** التي ينشئها الموظف عند طلب الحساب (٨ خانات على الأقل).
- **نسيت كلمة المرور** ⇒ يصل **رمز OTP** من ٦ أرقام إلى بريد الموظف، صالح ١٠ دقائق ومحدود بـ ٥ محاولات.
- طلب إنشاء الحساب يذهب إلى **مدير النظام** الذي يرى تفاصيله ويقبله أو يرفضه مع بيان السبب،
  ويصل قرار الاعتماد/الرفض للموظف بالبريد.

## ٤. صلاحيات مدير النظام (الأدمن)

- لوحة إحصائيات: الطلبات حسب الحالة والنوع، الموظفون، آخر العمليات على النظام.
- الاطلاع على كل الطلبات والبحث بالرقم المدني، واتخاذ القرار نيابةً عن الجهة، و**حذف الطلبات** ومرفقاتها.
- جدول بكل الموظفين مع: **تعديل البيانات**، **تغيير كلمة المرور**، **حذف الموظف**، وإنشاء حساب جديد مباشرة.
  كل عملية حسّاسة تتطلب **إدخال كلمة مرور الأدمن** للتأكيد.
- اعتماد أو رفض طلبات إنشاء الحسابات.

## ٥. أين تُحفظ الملفات والصور؟

في **Supabase Storage** داخل bucket خاص وغير عام اسمه `attachments`
(يُنشأ تلقائياً عند تشغيل ملف `supabase/schema.sql`).

**آلية الرفع (مهمة للنشر):** الملف يُرفع **مباشرة من متصفح المواطن إلى Supabase**
ولا تمر بايتاته عبر خادم الموقع — لأن منصات الاستضافة (Netlify ≈ ٦ ميجابايت،
Vercel ≈ ٤٫٥ ميجابايت) تحدّ حجم الطلب الواحد، وهو أقل من حد المرفقات لدينا (١٠ ميجابايت).
الخطوات:

1. عند اختيار الملف يطلب المتصفح من الخادم **رابط رفع موقّعاً** (Signed Upload URL)
   بعد التحقق من الصيغة والحجم — المسار المؤقت: `pending/<uuid>/<الحقل>.<الامتداد>`
2. المتصفح يرفع الملف مباشرة إلى Supabase Storage (يظهر «جارٍ الرفع…» ثم «✓ تم»).
3. عند حفظ الطلب يتحقق **الخادم** من وجود الملف وحجمه ونوعه فعلياً في التخزين
   (لا يثق ببيانات المتصفح)، ثم ينقله إلى `requests/<request_id>/...`
4. جدول `attachments` يحفظ **المسار فقط** لا الملف نفسه.

- الـ bucket غير عام: لا يمكن فتح أي ملف برابط مباشر. عند ضغط الموظف على «فتح المرفق»
  يمر الطلب عبر `/api/files/[id]` الذي يتحقق من الجلسة ثم يُنشئ **رابطاً موقّعاً مؤقتاً**
  (Signed URL) صالحاً ٥ دقائق فقط.
- حد الحجم (١٠ ميجابايت) والصيغ المسموحة مفروضة في أربع طبقات: المتصفح، إصدار رابط الرفع،
  التحقق عند الحفظ، والـ bucket نفسه.
- المفتاح العام `NEXT_PUBLIC_SUPABASE_ANON_KEY` يُستخدم في المتصفح للرفع فقط، ولا يمنح
  أي صلاحية بدون رابط موقّع من الخادم (كل الجداول عليها RLS بدون سياسات، والـ bucket خاص).

> جميع جداول قاعدة البيانات مفعّل عليها RLS **بدون سياسات عامة**، والوصول يتم حصراً من خادم
> Next.js بمفتاح `service_role`. لا يستطيع أي متصفح قراءة البيانات مباشرة.

## ٦. التشغيل خطوة بخطوة

### أ) إنشاء مشروع Supabase
1. أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** ⇒ **New query**، والصق محتوى الملف `supabase/schema.sql` كاملاً ثم **Run**.
   هذا ينشئ الجداول والفهارس والـ bucket الخاص بالمرفقات.
3. من **Project Settings ⇒ API** انسخ ثلاث قيم:
   - `Project URL`
   - `anon public` (مفتاح عام — للرفع من المتصفح)
   - `service_role secret` (سرّي — للخادم فقط)

> اختر منطقة المشروع الأقرب لعُمان (مثل `ap-south-1` مومباي أو `eu-central-1` فرانكفورت)
> — فسرعة الموقع تعتمد على قرب قاعدة البيانات من خادم الموقع.

### ب) إعداد متغيّرات البيئة
انسخ `.env.example` إلى `.env.local` واملأ القيم:

```bash
cp .env.example .env.local
```

```env
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
SESSION_SECRET=<ناتج: openssl rand -base64 48>
RESEND_API_KEY=re_xxx          # اختياري — بدونه تُطبع الرسائل في سجل الخادم
MAIL_FROM=بلدية السويق <no-reply@yourdomain.om>
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

### ج) إنشاء حساب مدير النظام الأول

**الطريقة الأسهل (بدون إعدادات):** الصق ملف [`supabase/create-admin.sql`](supabase/create-admin.sql)
في **SQL Editor** واضغط Run. ينشئ الحساب التالي:

| | |
|---|---|
| الرقم الوظيفي | `1001` |
| كلمة المرور | `Admin@2026` |

⚠️ غيّرها بعد أول دخول من: **الموظفون ← كلمة المرور**. ولتوليد تشفير كلمة مرور أخرى:

```bash
npm run hash -- MyNewPass123
```

**الطريقة الثانية (من الطرفية):** تحتاج `.env.local` مكتملاً:

```bash
npm run seed:admin
```

أو بتمرير القيم مباشرة:

```bash
npm run seed:admin -- --number=1001 --name="سعيد محمد الهنائي" --email=admin@suwaiq.gov.om --password=Admin1234
```

### د) التشغيل

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:3000> — ودخول الموظفين من <http://localhost:3000/login>.

## ٧. البريد الإلكتروني

الإرسال عبر [Resend](https://resend.com):
1. أنشئ حساباً واحصل على `RESEND_API_KEY`.
2. وثّق نطاق الدائرة (Domain) واضبط `MAIL_FROM` على بريد داخل النطاق.

بدون مفتاح البريد يعمل النظام بالكامل، لكن الرسائل (بما فيها رموز OTP) **تُطبع في سجل الخادم**
بدل إرسالها — وهو مناسب أثناء التطوير والتجربة.

## ٨. بنية المشروع

```
src/
├─ app/
│  ├─ page.tsx                     الصفحة الرئيسية والخدمات الثلاث
│  ├─ apply/[type]/                نموذج تقديم الطلب + إجراء الحفظ والرفع
│  ├─ track/                       تتبّع الطلبات بالرقم المدني (للمواطن)
│  ├─ (auth)/                      الدخول، طلب حساب، نسيت كلمة المرور (OTP)
│  ├─ (app)/dashboard/             واجهة الموظف: الوارد، الطلبات، الإشعارات، القرار
│  ├─ (app)/admin/                 لوحة الأدمن: الطلبات، الموظفون، طلبات الحسابات
│  └─ api/files/[id]/              فتح المرفقات برابط موقّع مؤقت
├─ components/                     مكوّنات الواجهة (عربية RTL)
└─ lib/
   ├─ supabase.ts / storage.ts     الاتصال بقاعدة البيانات والتخزين
   ├─ auth.ts                      الجلسات، تشفير كلمات المرور، الصلاحيات
   ├─ workflow.ts                  منطق مسار الطلب بين الأقسام
   ├─ notify.ts / mail.ts          الإشعارات والبريد
   └─ validation.ts                التحقق من المدخلات (رقم مدني، اسم عربي، هاتف…)
supabase/schema.sql                مخطط قاعدة البيانات + إنشاء bucket المرفقات
scripts/create-admin.mjs           إنشاء حساب الأدمن الأول
```

## ٩. النشر على Netlify

ملف `netlify.toml` جاهز في المشروع (أمر البناء + إضافة Next.js + استثناء المتغيّرات
العامة من فحص الأسرار). الخطوات:

### أ) ارفع المشروع إلى GitHub

```bash
git init
git add .
git commit -m "بوابة استثمار المواقع الحكومية — دائرة البلدية بالسويق"
git branch -M main
git remote add origin https://github.com/<حسابك>/<المستودع>.git
git push -u origin main
```

> ملف `.gitignore` يستثني `.env.local` — لا تضع المفاتيح داخل المستودع أبداً.

### ب) إنشاء الموقع على Netlify

1. من netlify.com: **Add new site ⇒ Import an existing project ⇒ GitHub** واختر المستودع.
2. Netlify يقرأ `netlify.toml` تلقائياً — اترك أمر البناء كما هو (`npm run build`).
3. قبل الضغط على Deploy افتح **Add environment variables** وأضف:

| المتغيّر | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | مفتاح `anon public` |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح `service_role` — **سرّي** |
| `SESSION_SECRET` | ناتج `openssl rand -base64 48` |
| `RESEND_API_KEY` | مفتاح البريد (اختياري) |
| `MAIL_FROM` | `بلدية السويق <no-reply@نطاقك>` |
| `NEXT_PUBLIC_APP_URL` | رابط الموقع بعد النشر |

4. **Deploy site**. بعد ظهور الرابط (مثل `https://suwaiq-investment.netlify.app`)
   ارجع وعدّل `NEXT_PUBLIC_APP_URL` إلى هذا الرابط ثم **Trigger deploy ⇒ Clear cache and deploy**
   (هذا المتغيّر يُستخدم في روابط رسائل البريد).

### ج) بعد النشر

- شغّل `npm run seed:admin` **من جهازك** مرة واحدة لإنشاء حساب الأدمن — يكتب في نفس
  قاعدة بيانات Supabase التي يستخدمها الموقع المنشور.
- للنطاق الرسمي: **Domain settings ⇒ Add custom domain**، وشهادة HTTPS تُصدر تلقائياً.

### ملاحظات تخص Netlify

- **حجم الطلب**: دوال Netlify تحدّ الطلب بـ ٦ ميجابايت تقريباً — لذلك تُرفع المرفقات
  مباشرة إلى Supabase من المتصفح (انظر القسم ٥)، فلا يتأثر حد الـ ١٠ ميجابايت.
- **فحص الأسرار**: `SECRETS_SCAN_OMIT_KEYS` في `netlify.toml` يستثني المتغيّرات العامة
  (`NEXT_PUBLIC_*`) فقط. لا تضف `SUPABASE_SERVICE_ROLE_KEY` إلى هذه القائمة إطلاقاً.
- **منطقة الدوال**: الافتراضي أمريكا. لتقليل زمن الاستجابة اجعل مشروع Supabase في منطقة
  قريبة، أو فعّل تشغيل الدوال في منطقة أقرب من إعدادات الخطة المدفوعة.

### تشغيل خارج المنصات المُدارة

```bash
npm run build
npm start
```
